As input size grows past the context window size:

A] Current prompt is manageable but history is too large -> manipulate history:
    1] drop older history first
    system prompt + recent history + current prompt

    2] summarize the history - with another model
    system prompt + summarized history + current prompt

    3] summarize older history and keep recent history
    system prompt + summarized older history + recent history + current prompt

    4] store older history externally and use RAG to fetch relevant pieces from it
    system prompt + RAG extracted history + recent history + current prompt

# --------

B] Current prompt itself is too large for the context window (history being too long is implied)
 1] chunk input prompt into k chunks (assume 2 here)
  a] system prompt + chunk processing instructions + (optional: summarized / RAG history) + prompt chunk 1 -> intermediate output 1
  b] system prompt + chunk processing instructions + (optional: summarized / RAG history) + prompt chunk 2 -> intermediate output 2
  c] system prompt + combination processing instructions + summarized / RAG history + intermediate output 1 + intermediate output 2 -> final output

During chunk processing; summarized / RAG history can be optional if current input can be understood without much help 
        from past context. (is natural language text and we can summarize it).

Otherwise, say current prompt is large code chunk; we may not be able to summarize it and may need past info to 
        understand it.
